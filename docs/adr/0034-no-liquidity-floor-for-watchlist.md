# ADR-0034: ウォッチリスト層には流動性フロアを適用せず、非通過の内訳を件数で出す

- ステータス: 承認済み
- 日付: 2026-11-18
- 関連: [#57](https://github.com/Ries630/StockCopilot/issues/57)、[#56](https://github.com/Ries630/StockCopilot/issues/56)、[ADR-0010](0010-three-layer-universe.md)、[ADR-0011](0011-event-based-screen-thresholds.md)

## 背景

`screen.py` は母集団のすべての銘柄に、20 日平均売買代金の流動性フロア（`MIN_TURNOVER_JPY` 10 億円 /
`MIN_TURNOVER_USD` 1 億ドル）を最初にかけていた。フロアは、知らない銘柄を拾う探索ユニバースから
板の薄い銘柄を落とすための品質管理である。

ウォッチリスト層（[ADR-0010](0010-three-layer-universe.md)）は、人が板の薄さを承知で入れる層である。
#56 の調査で、ウォッチリストの銘柄が母集団には入るのに、フロアで黙って落ちることを確認した。
非通過は `None` だけで返っていたので、出力からは「事象が起きていない」のか「そもそも評価されて
いない」のかを区別できず、フロア未満の銘柄は永久に候補に出なかった。

## 決定

- 母集団の各銘柄に層（`watch` / `explore`）を持たせる。両方に載る銘柄はウォッチリスト層として扱う。
- 流動性フロアは探索層にだけ適用する。閾値は変えない。事象ゲート
  （[ADR-0011](0011-event-based-screen-thresholds.md)）は両層とも維持する。
- 評価の結果は「候補」か「非通過の理由」（流動性フロア未満 / 事象なし / データ不足）のどちらかにする。
- ウォッチリスト層の非通過の内訳だけを出力する。探索層で事象が起きないのは常態なので出さない。
- 内訳は件数だけにし、テキスト出力でも `--json` でも銘柄を出さない。ウォッチリストは購入意図
  そのもので、出力は public リポジトリに貼られうる（[ADR-0008](0008-no-holdings-in-repo.md)）。
- `--json` の内訳は新しいトップレベルの `layers` に置き、`screen.jp` / `screen.us` には足さない。
  `screen` は中間表現へそのまま写す値で、JSON Schema が追加のキーを拒否する
  （[ADR-0021](0021-json-schema-for-report-contract.md)）。

代替案を比較した記録はない。

## 受け入れた代償

- ウォッチリスト層の板の薄い銘柄が候補に出るようになる。ギャップやスプレッドで確定足の値動きが
  大きく出やすいので、候補の分析（`analyze.py`）で板の薄さを踏まえて読む必要がある。
- 内訳が件数だけなので、どの銘柄が事象なしだったかは出力から分からない。ウォッチリストが少ない
  前提では件数で足りるが、多くなると切り分けに手間がかかる。

## 再評価の条件

- ウォッチリストの銘柄数が増え、件数だけでは非通過の銘柄を特定できなくなったとき。
- 長期保有枠（#58）のように、層ごとに通過条件を変える必要が出たとき。
