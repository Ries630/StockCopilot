# ADR-0017: スクリーニングのレポートには買いの判断を書く（コード側の分離は維持する）

- ステータス: 承認済み
- 日付: 2026-08-13
- 関連: [#41](https://github.com/Ries630/StockCopilot/issues/41)、[ADR-0006](0006-screener-does-not-decide-buys.md)

## 背景

[ADR-0006](0006-screener-does-not-decide-buys.md) は `screen.py` が買いを判定せず、
採否を `analyze.py` に通すことを決めた。狙いは誤検知のコストを**分析 1 回分の工数**に
抑えることで、この目的は `analyze.py` を回した時点で達成される。

`stock-screen` スキルの運用規範を作る過程で、この決定を
「レポートにも買う / 買わないの結論を書かない」まで広げて適用していた。
SKILL.md の大原則は「書いてよいのは『何が起きたか』と『どの水準が意味を持つか』まで」
とだけ書いており、**強弱の評価を断定してよいかが読み取れない**状態だった。

2026-08-13 の定期実行で、その副作用が出た。同じレポートの中に 3 箇所:

- 「上位は『構造は強いが勢いは中立』」— 週足 -DI 20.24 > +DI 19.62 という数字を
  持っているのに、下向きが優勢とは書いていない
- 「突破幅が大きいのではなく、突破したこと自体が事象」— score 0.6 ATR は小さい、で足りる
- 「注目水準: …（エントリーを検討するなら意味を持つ水準。買い推奨ではない）」—
  出力テンプレート由来の免責が毎回付く

数字はレポートに載っているので、読み手が毎回自分で評価を組み直す必要があった。
りーすさんからの指摘は「出力された評価を見て判断するのは私なので遠回しな言い方を
しなくてよい」というもので、**結論の有無ではなく表現の濁りが問題**だった。

兄弟プロジェクトの TradingCopilot は同じ構造を別の切り方で運用している。
`swing/screen.py` には「ここに判断ロジックを足してはならない」とコード側の禁止がある一方、
`swing-check` の出力フォーマットは `判断: ホールド / 積増し / 部分利確 / クローズ（★信頼度）`
と明確にラベルを出す。**コードの分離とレポートの表現を別の問題として扱っている。**

## 決定

`screen.py` のコードは変更しない（ADR-0006 の決定を維持する）。
レポート側では**強弱の評価を断定して書き、`判断: 買い` まで書く**。

`stock-screen` のラベルを「次アクション」から「判断」に一本化し、
`買い` / `見送り（理由）` / `決算後に再判定` / `保留（材料不足）` の 4 種にする。

## 検討した代替

- **現状維持（レポートにも結論を書かない）** — 上記 3 箇所の濁りが実例として出たので落とした。
  結論を避けること自体は害が無いが、**それが強弱の評価まで波及する**ことが運用で分かった
- **ラベルを `エントリー検討` という婉曲な語にする** — 「買い」と言い切らずに
  判断だけ伝える案。りーすさんの判断で落とした。**遠回しを外すのが今回の趣旨なので、
  ラベルだけ婉曲に残すと元の状態に戻る**
- **「次アクション」を残したまま「判断」行を別に足す** — ラベルが 2 系統になり、
  「判断: 買い」と「次アクション: 判断へ」が同じことを二重に言う。落とした
- **★信頼度を付ける（`swing-check` 方式）** — 付けない。
  `stock-check` が「現物のホールド判断は perp より単純で、毎回付けると形骸化する」として
  ★を落としているので、現物側の 2 スキルで揃える
- **ADR-0006 を廃止して置換する** — しない。ADR-0006 の決定はコードに対するもので、
  今回の変更と矛盾しない。廃止すると「`screen.py` に判定ロジックを足さない」という
  現に有効な決定まで消える

## 結果

- **判断の当たり外れが記録として残るようになる。** ジャーナルに「買い」が蓄積するので、
  外したときに振り返りの対象になる。「候補を出しただけ」という逃げ道は無くなる
- **機械抽出とレポート判断の間に、決定的でない裁量が明示的に入る。**
  `screen.py` の通過条件は再現可能だが、「買い」の判断はスキル（LLM）の裁量で、
  同じ入力から同じ出力が出る保証は無い。ADR-0006 が守っているのはコードの側だけになる
- **ラベル体系が 2 系統になる。** 保有 = 5 ラベル（ホールド / 積増し / 部分利確 / 売却 / 保留）、
  非保有 = 4 ラベル（買い / 見送り / 決算後に再判定 / 保留）。
  同じジャーナルの同じ日付エントリに両方が並ぶため、取り違えの余地が増える
- **「保留」だけが 2 系統に共通する語になる。** どちらも「データ不足で判定が成立しない」
  意味で使うので、意味は割れていない

## 再評価のサイン

- ジャーナルに溜まった「買い」判断の当たり外れを見て、精度が低ければラベルを戻す。
  **判定に必要な件数は決めていない（未検討）** — 2026-08-13 時点で
  スクリーナーの候補は 1 日あたり 0〜2 件で、母集団を 15 → 25 銘柄に広げた直後にあたる
- 2 系統のラベルの取り違えがジャーナル上で実際に起きたら、体系の統合を検討する
