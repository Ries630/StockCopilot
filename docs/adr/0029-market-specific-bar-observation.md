# ADR-0029: 確定足の更新状態を市場別に判定する

- ステータス: 承認済み
- 日付: 2026-08-22
- 関連: Issue #75

## 背景

夕方ブリーフは JP / US の確定足日を `bars.jp` / `bars.us` に持つ一方、更新状態は
トップレベルの `stale_bars` 1 個だけで表していた。この構造では、一方の市場だけ
確定足が進んだ状態を表せない。また前回足との比較と `stale_bars` の記入を LLM が
行っており、同じ確定足から判断・水準・トリガーを再生成できてしまう。

市場別状態を導入するにあたり、確定足日を取得できない市場があったときに、取得できた
市場だけ続行するか、ブリーフ全体を停止するかを決める必要がある。保有分析の中間表現には
市場フィールドがないが、契約上 JP は JPY、US は USD と対応している。

## 決定

中間表現を schema v2 に上げ、JP / US ごとに `updated` / `unchanged` / `initial` /
`unavailable` を持つ。前回足との比較、更新市場の選別、停滞市場の前回結果との合流は
決定的コードで行う。`unavailable` の市場だけを停止し、取得できた市場は続行する。

保有から市場への変換は `currency` の JPY / USD 対応から導出し、その規則を市場別合流の
共通処理 1 か所に置く。`holdings[].market` は追加せず、`market_tone` も市場別にしない。

## 検討した代替

- **片市場でも確定足日を取得できなければブリーフ全体を停止する。** 取得できた市場の
  新しい観測まで失うため不採用。
- **`stale_bars` を残す。** JP のみ更新 / US のみ更新を表現できないため不採用。
- **取引日カレンダーや別データ源で休場とデータ遅延を判別する。** Issue #75 のスコープ外で、
  現在取得している確定足日だけを比較する方針のため不採用。
- **`holdings[].market` を追加する。** 現在の契約にある通貨と市場の一対一対応から決定的に
  導出でき、同じ事実を二重に持つことになるため不採用。

## 結果

- schema v1 の中間表現を新しい契約の入力として扱えなくなる。移行時の前回足は既存の
  `reports/latest.json`、それが無い場合は旧ジャーナルから読み取る必要がある。
- `unavailable` / `unchanged` の市場では新しい分析を生成できず、前回結果を引き継ぐ。
- 取引日カレンダーを持たないため、確定足が進まない理由を休場かデータ遅延か断定できない。
- 保有市場の導出は JPY=JP / USD=US という現在の契約に依存する。

## 再評価のサイン

- JPY建てのUS市場商品など、通貨と市場が一対一でなくなったとき。
- 休場とデータ遅延を自動で区別する必要が生じ、取引日カレンダーを導入するとき。
- 一市場の取得不能でもブリーフ全体を止める必要がある障害が実際に発生したとき。
