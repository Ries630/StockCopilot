# ADR-0032: 取得した決算日を記録し、決算直後の切り替わりで警告を落とさない

- ステータス: 承認済み
- 日付: 2026-11-17
- 関連: ADR-0009 / ADR-0016 / ADR-0008

## 背景

`lib/earnings.py` は yfinance の `calendar` の決算日を 1 つ取り、警告期間（前後 7 日）に入れば
`⚠` を付ける。ところが yfinance の決算日は、決算が過ぎると数日のうちに次回の予定日へ
切り替わる。切り替わった日の注記は「決算 YYYY-MM-DD（あと約 90 日）」になり、決算直後の
値動きに付くはずの「直近の値動きは決算反応の可能性」という警告が消える。

夕方ブリーフの定期実行では、2026-11-04 と 2026-11-11 の 2 回この切り替わりが起きた。どちらも
LLM が前回の中間表現の注記と見比べて気付き、追跡対象外の `journal/lessons.md` に
「前回の JSON と照合する」というルールを足して補っていた。決算反応をテクニカルの進捗として
読むと判断を誤るので（ADR-0009）、LLM が覚えているかどうかに頼る状態は避けたい。

## 決定

`earnings_note()` が取得した決算日を `data/earnings_seen.json` に市場とティッカーごとに記録する。
注記を作るときは、取得値が警告期間の外（または取得できない）で、記録に当日か警告期間内に
過ぎた決算日があれば、その日で「直近決算」の警告を出し、末尾に `(次回 …)` を添える。警告期間より
前に過ぎた日は記録から消す。まだ来ていない日で今回の取得値と違うものも消す。推定日から確定日への
変更や延期で置き換わった予定を残すと、実際には無かった決算日で警告するため。

保有銘柄の決算日の並びは保有を推測させるので、記録は追跡対象外の `data/` に置く（ADR-0008）。
記録が読めない・書けない場合は警告を stderr に出し、取得値だけで判定する従来の動作に戻る。

## 検討した代替

- **前回の中間表現（`reports/latest.json`）の注記と照合する。** 注記は文字列で日付が構造化
  されておらず、照合のために文言を解析することになる。中間表現が無い単体分析
  （`analyze.py` を直接呼ぶ場合）や `screen.py` では使えない。
- **yfinance の `get_earnings_dates()` で過去の決算日も取る。** 1 銘柄ごとにリクエストが
  増え、日本株では取得できないことが多い。データ源の差し替えを `lib/datasource.py` に閉じる
  方針（ADR-0004）にも、取得経路を増やす分だけ反する。
- **LLM のルール（`journal/lessons.md`）のままにする。** 判定は日付の比較だけの機械的な
  処理で、覚えているかどうかに結果が左右されるため不採用。

## 受け入れた代償

- 記録は実行したマシンにしか残らない。決算日をまたいで一度も実行しなかった場合
  （休止中、別のマシン）は補えず、取得値どおりの行が出る。
- `earnings_note()` が呼ばれるたびに小さな JSON を読み書きする。
- 予定日が更新されないまま過ぎ、そのあとで延期後の日付に変わった場合は、過ぎた予定日を
  決算日と区別できず、実際には無かった決算日で警告する。過ぎる前に変更を取得していれば
  起きない。

## 再評価の条件

- データ源を yfinance 以外に替え、過去の決算日を 1 リクエストで取れるようになったとき。
