# ADR-0024: 用語の説明は本文ではなくポップオーバーに置く

- ステータス: 承認済み
- 日付: 2026-08-20
- 関連: [#60](https://github.com/Ries630/StockCopilot/issues/60)

## 背景

りーすさんはテクニカル分析の用語に疎く、軽い説明が読めると助かる。一方で
**毎日同じ説明がレポート本文に入るのは避けたい**という要望がある。

レポートは日次で出る。本文は「今日どうだったか」と「だからどうするか」のための
場所であり、そこへ説明を混ぜると、**日々変わる情報と一度読めば済む情報が
同じ密度で並ぶ**。読み手は毎日、同じ文章を読み飛ばす作業をすることになる。

HTML には外部リソースを読み込まない制約がある
([ADR-0020](0020-intermediate-report-json.md) の HTML 要件)。
`tests/test_report.py` が `<script` の不在を固定している。

## 決定

用語を小さなラベルにし、**押したときだけ**説明を出す。HTML の Popover API
(`popovertarget` 属性 + `popover` 属性) を使い、**JavaScript は書かない**。
未対応のブラウザ向けに `title` 属性を併記する。

説明の実体は `report.py` の `GLOSSARY` に用語ごと 1 つだけ持ち、ページ末尾に
まとめて出す。同じ用語が何度カードに出ても、参照するポップオーバーは同じものになる。

## 検討した代替

**1. 本文に書く。** 却下。要望そのものに反する。

**2. `title` 属性だけにする。** 却下。タッチ端末ではホバーできず読めない。
表示までの遅延があり、長文は途中で切られる。ただし**落ち先としては併記する**。

**3. `<details>` で折りたたむ。** 却下。開くとレイアウトが押し広がる。
カードの中に置くと図の位置が動き、隣のカードとの比較がずれる。

**4. JavaScript でツールチップを実装する。** 却下。インラインの `script` を足すと、
HTML の自己完結性をテストで担保している前提 (`<script` が無いこと) を崩す。
得られるのは配置の自由度だけで、見合わない。

## 結果

**Popover API 非対応のブラウザでは押しても何も起きない。** `title` のホバーだけが
残る。Chrome 114+ / Safari 17+ が必要で、それより古い環境は切り捨てた。

**説明文に書式を持てない。** 素のテキストとしてエスケープするため、強調も改行も
入れられない。1〜2 文で言い切れる説明だけを書くことになる。

**ページ末尾のポップオーバー本体が用語の数だけ増える。** 全部を 1 ページに載せる
方式なので、用語を増やすと HTML が肥大する。

**ポップオーバーは画面中央に出る。** 押した語の隣には出ない (CSS Anchor
Positioning を使えば寄せられるが、対応が揃っていないので選ばなかった)。

## 再評価のサイン

- 用語が増えて HTML が重くなったら、用語集を別ページに分ける
- 説明を本文に書きたくなる場面が出てきたら、それは説明ではなく判断の一部である
  可能性が高い。`prose` 側に置けないかを先に疑う
- CSS Anchor Positioning が主要ブラウザで揃ったら、押した語の隣に出す
