# ADR-0035: 長期保有枠を母集団の外に置き、買付期限までの残日数を毎回出す

- ステータス: 承認済み
- 日付: 2026-11-18
- 関連: [#58](https://github.com/Ries630/StockCopilot/issues/58)、[#56](https://github.com/Ries630/StockCopilot/issues/56)、[ADR-0006](0006-screener-does-not-decide-buys.md)、[ADR-0010](0010-three-layer-universe.md)、[ADR-0034](0034-no-liquidity-floor-for-watchlist.md)

## 背景

優待や高配当を目的に長く持つ銘柄では、問うべきことが「何かが起きたか」ではなく
「権利付き最終日までに、どの水準で買うか」になる。権利付き最終日を過ぎると、次の機会は
最長で 1 年後になる。

母集団の 3 層（[ADR-0010](0010-three-layer-universe.md)）には、この銘柄の置き場所がなかった。
ウォッチリストに入れても、候補に出るのは事象ゲート（[ADR-0011](0011-event-based-screen-thresholds.md)）
を通った日だけで、期限までの残日数はどこにも出なかった。

## 決定

- 追跡対象外の `config/watchlist.py` に `LONG_TERM_STOCKS` を置く。1 銘柄は
  `ticker` / `shares`（必要株数）/ `buy_by`（権利付き最終日のリスト）/ `purpose` を持つ。
  `buy_by` をリストにするのは年 2 回の銘柄があるため。市場は `detect_market()` で推定し、持たせない。
- パース・検証・次の期限の選択・状態判定は `lib/long_term.py` に置く。次の期限は、判定日以降で
  最も近い `buy_by` とする（当日を含む）。すべて過去なら警告を出す。
- 状態は実効保有に含まれるかで決める（含まれれば保有中、含まれなければ買付予定）。
  手で「保有中」へ移し替える運用にしない。保有データを読めない回は「状態不明」として買付予定と同じく表示する。
- `screen.py` は「買付予定」の節を設け、買付予定の銘柄を流動性フロアも事象ゲートも通さずに
  常に全件出す。出すのは現値 / 20 日レンジ内の位置 / 残日数 / 必要株数 / 概算必要額で、
  買い判断はしない（[ADR-0006](0006-screener-does-not-decide-buys.md) を維持）。
- 長期保有枠の銘柄は候補抽出の母集団から外す。買うと決めている銘柄を事象で拾い直す意味がない。
- 買付予定の銘柄はティッカーを出力に出す。節の目的が銘柄ごとの期限の提示なので、件数だけでは
  用をなさない。保有中の銘柄は件数だけを出す（保有一覧を出力に残さない。
  [ADR-0008](0008-no-holdings-in-repo.md)）。

## 検討した代替

- **ウォッチリスト層に期限を足す** — ウォッチリストは事象ゲートで候補を拾う層
  （[ADR-0034](0034-no-liquidity-floor-for-watchlist.md)）で、期限の銘柄を毎回全件出す扱いと両立しない。
- **権利付き最終日を自動で取得する** — yfinance は権利確定日を安定して返さない。手で書く日付の
  ほうが誤りに気付きやすく、すべて過去になれば警告で書き足しを促せる。

## 受け入れた代償

- `buy_by` は手で更新する。書き足しを忘れると、警告が出るまで次の期限が出ない。
- 残日数は暦日で数える。営業日ではないので、連休を挟むと実際に買える日数は少ない。
- 買付予定の銘柄はティッカーが出力に出る。出力を貼り付けるときは、保有と同じく伏せる必要がある。

## 再評価の条件

- 権利付き最終日を決定的に取得できるデータ源（[#20](https://github.com/Ries630/StockCopilot/issues/20) など）が整ったとき。
- 保有中の長期保有枠に固有の注記や判断ラベル（[#59](https://github.com/Ries630/StockCopilot/issues/59)）を入れるとき。
