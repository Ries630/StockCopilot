# ADR-0013: シグナルの事後検証までを作り、フルバックテストは作らない

- ステータス: 提案
- 日付: 2026-08-09
- 関連: [#17](https://github.com/Ries630/StockCopilot/issues/17)（OPEN）

## 背景

`config/universe.py` の閾値は手置きの値になっている。

- `MIN_MOVE_IN_ATR = 1.5`
- `MIN_BREAK_IN_ATR = 0.3` — コメント自身が「運用しながら調整する前提の値」と明記
  （[ADR-0011](0011-event-based-screen-thresholds.md)）

閾値を最適化する前に、**そもそも通過条件が無条件保有に対して優位性を持つのか**を
確かめたい。ここで差が出ないなら、閾値の調整以前にルール自体を見直す必要がある。

制約が 2 つある。

- **機械化された出口ルールが存在しない。** 出口判断は `analyze.py` の出力を見て人が決める
  設計（[ADR-0006](0006-screener-does-not-decide-buys.md)）
- 探索ユニバースは 18 銘柄。数年分でもサンプルは数百件程度

## 決定

各営業日について、その日以前の確定足だけで通過条件を評価し、通過銘柄の t+5 / t+20
営業日リターンをベースラインと比較する**シグナルの事後検証**までを作る。

建玉・手仕舞い・枚数・資金曲線を再現する**フルバックテストは作らない。**

## 検討した代替

- **フルバックテスト（ポートフォリオ再現）** — 建玉・手仕舞い・枚数・資金曲線の再現には
  出口ルールが必要だが、機械化されたルールが存在しない。**存在しないルールは再現できない**
- **検証結果を `screen.py` の判断ロジックに組み込む** —
  [ADR-0006](0006-screener-does-not-decide-buys.md) の分離を崩す。成果物は閾値を決める
  材料に留める

## 結果

- **資金曲線・最大ドローダウンを語れない。** 評価できるのは通過群とベースラインの
  リターン分布（平均・中央値・勝率・サンプル数）まで
- サンプルが数百件程度なので、「閾値 A が B より明確に良い」という強い結論は出せない。
  期待するのは**サニティチェックであって最適化ではない**

## 未検証の点

- **未着手。** 優先度は低く、運用を続けてデータが溜まってからでも遅くないと判断している
- 通過条件が無条件保有に対して優位性を持つかは分かっていない。これが確認できるまで
  [ADR-0011](0011-event-based-screen-thresholds.md) の閾値は根拠が上下の目安だけのままになる
- 過去日への遡及でも [ADR-0005](0005-completed-bars-only.md) の規律
  （t 時点の判定に t+1 以降のデータを使わない）を守る実装ができるかは未検証
