# ADR-0011: 通過条件は状態ではなく事象にし、突破幅に下限を置く

- ステータス: 承認済み
- 日付: 2026-08-09
- 関連: `b547746`、[#3](https://github.com/Ries630/StockCopilot/issues/3)、[#11](https://github.com/Ries630/StockCopilot/pull/11)

## 背景

`screen_one()` の突破判定は `if break_atr:` で、ゼロ以外を無条件に通していた。

実測 (`uv run screen.py --market us`):

| 項目 | 値 |
|---|---|
| 20 日高値 | $499.44 |
| 確定終値 | $499.86 |
| 日次 ATR | 約 $18 |
| 突破幅 | **0.02 ATR** |

表示も `score 0.0 ATR` / `(ATR 0.0 倍)` となり、候補として意味を持たなかった。

このスクリーナーは**事象が起きたことだけを条件にする**設計で、「レンジの端に近い」という
状態を条件にしない。近さで通すと母集団の一定割合が常に該当し、候補ゼロが構造的に
起きなくなる (埋め草を出し続ける) ためだった。突破幅に下限が無いと、避けたはずの
その状態に戻る。

変化率側には `MIN_MOVE_IN_ATR = 1.5` があり、**突破側にだけ閾値が無い非対称**でもあった。

当時の母集団は 18 銘柄（[ADR-0010](0010-three-layer-universe.md) のウォッチリスト追加と同日）。

## 決定

`MIN_BREAK_IN_ATR = 0.3` を追加し、`break_atr >= MIN_BREAK_IN_ATR` で判定する。
上抜け・下抜けの両方に同じ閾値を適用する。

## 検討した代替

Issue では 0.25〜0.5 を候補にしていた。

- **0.25** — ATR の 1/4 程度では日中のノイズと区別しきれない
- **0.5** — もう一方の条件 `MIN_MOVE_IN_ATR = 1.5` と比べて厳しく、候補ゼロが常態化しうる
- **上抜けと下抜けで別の閾値にする** — `break_atr` は方向を持たず幅だけを見ており、
  非対称にする根拠が現時点で無い
- **実データの分布を見てから決める** — [#3](https://github.com/Ries630/StockCopilot/issues/3) は
  そうする方針だった。落としたのは、分布が母集団に依存し、その母集団
  （[ADR-0010](0010-three-layer-universe.md) のウォッチリスト、探索ユニバースの拡張）が
  これから動くため。18 銘柄では標本が薄く、見ても決め切れない。閾値は定数 1 個で
  差し替えコストがほぼゼロなので、運用しながら調整する前提で先に決め打ちした

## 結果

- **0.3 が妥当かどうかを今は答えられない。** 分布を見ずに決めており、根拠は上下の目安だけ
- 0.3 ATR 未満で抜けて走り出した銘柄は、その日は候補にならない。翌日以降に変化率側
  (`MIN_MOVE_IN_ATR`) で拾えるかに依存する
- 候補ゼロの日が増える。これは意図した副作用で、埋め草を出さないことと引き換え

## 再評価のサイン

- **シグナルの事後検証の結果**（[ADR-0013](0013-no-full-backtest.md)）。
  通過群とベースラインに差が出ないなら、閾値の調整以前にルール自体を見直す
- **母集団が固まったとき。** 分布を見て決め直せる
