# ADR-0001: 独立した兄弟プロジェクトとして立て、指標エンジンはコピー流用する

- ステータス: 承認済み
- 日付: 2026-08-06
- 関連: `4fa1e92`、設計メモ `~/.claude/plans/tradingcopilot-trading-copilot-morning-b-toasty-duckling.md`

## 背景

既に 2 つのプロジェクトがあった。

- **TradingCopilot** — 仮想通貨の前向き分析。`swing-check` / `morning-brief` を持ち、
  自動発注のための本番鍵を扱う
- **Investment** — 株式と仮想通貨の取引履歴レポート (記帳)。python3 運用

ここに株式 (日本株・米国株、現物) のスクリーニングと保有分析を足したい。
自動売買はしない。

争点は 2 つあった。**「前向き分析 vs 記帳」** のどちらに寄せるか、そして
**crypto の本番鍵・自動発注・uv 運用系統から隔離するか**。

既存プロジェクト間で module 共有は行われていない。指標エンジンの実体は
TradingCopilot の `swing/_analyze.py` (pandas + numpy + `ta`) にあり、
RSI / MACD / EMA / Bollinger / ATR / StochRSI / OBV / ADX と 20・60 日高安を持つ。
これらは資産クラス非依存でそのまま使える。

## 決定

新規の兄弟プロジェクトとして立て、TradingCopilot の指標エンジンをコピーして持ち込む。
プロジェクト間の module 共有はしない。

## 検討した代替

- **TradingCopilot に同居させる** — 株式分析は forward-looking で `swing-check` と同じ活動
  なので、活動の性質としては最も近い。落としたのは、データ源 (株価フィード)・通貨・
  市場時間が crypto と全く別系統であり、かつ**自動発注の本番鍵と対象が混在して
  リスク面積が増える**ため
- **Investment に同居させる** — python3 運用の記帳用途で、前向き分析とは性質が違う
- **指標エンジンを共有 module として切り出す** — 既存プロジェクトも跨プロジェクトの
  module 共有をしておらず、現行の慣習に反する

## 結果

- **指標エンジンが 2 箇所に存在する。** TradingCopilot 側でバグを直しても指標を足しても、
  こちらには伝播しない。手で移す必要がある
- 移植元との差分を検出する仕組みが無い。テストも別々に持つ
- crypto と株式を横断した分析 (資産全体のリスク) はどちらのプロジェクトでもできない。
  横断は記帳側の Investment が担う
- 発注に関わるコードと鍵をこのプロジェクトに一切持ち込まない前提が立つ。
  証券会社の取引 API を追加しないという規範はこの隔離の一部
