# ADR-0005: 判定は確定足のみで行う

- ステータス: 承認済み
- 日付: 2026-08-06
- 関連: `4fa1e92`、`564ad38`、[#2](https://github.com/Ries630/StockCopilot/pull/2)

## 背景

crypto は 24/7 で 00:00 UTC 引け。株式は取引所セッションと祝日があり、JP と US で
引け時刻が別 (JP 15:30 JST / US 16:00 ET)。日足の確定判定がカレンダー依存になる。

形成中の足を混ぜると、「20 日レンジを抜けた」が引け後に戻る誤検知になる。
TradingCopilot の `swing/_analyze.py` には `drop_forming_bar` /
`fetch_completed_daily_bars` として同じ規律があり、考え方を移植できる。

この種の誤りは **look-ahead バイアスとして静かに混入し、出力を見ても気づけない**。

## 決定

判定は確定足のみで行う。`lib/datasource.py` の `drop_forming_bar()` が、市場ごとの
引け時刻 (JP 15:30 JST / US 16:00 ET、いずれも 30 分のバッファ付き) で形成中の足を落とす。
週足は当週を落とす。

## 検討した代替

- **形成中の足を含める** — ブレイクの誤検知が入る。落とした理由は上記のとおり
- （他案の記録は無い。移植元に既にこの規律があり、前提として持ち込んでいる）

## 結果

- **場中の値動きに反応できない。** 日中に抜けた銘柄はその日の候補にならず、引けを待つ
- 引け後 30 分はまだ前日の足で判断する
- **祝日・半日立会いのカレンダーは持っていない。** 時刻のバッファだけなので、
  休場日の扱いは yfinance が返す足に依存する
- 現在時刻を直接読むと実行が場中かどうかで結果が変わり決定的に検証できないため、
  `drop_forming_bar()` に判定時刻の注入点 (`now`) を設けた
- 確定足ベースのトリガー (「日足終値で X を割ったら」) は、決算のギャップに
  飛び越えられる。トリガーが有効かを別に判断する必要が生じた
  → [ADR-0009](0009-earnings-date-as-trigger-validity.md)
- 過去日へ遡って判定する処理を書くときも同じ規律を守る必要がある
  ([#17](https://github.com/Ries630/StockCopilot/issues/17))
