# ADR-0033: EMA200 を収束させるため、analyze.py は 600 本の確定足で指標を計算する

- ステータス: 承認済み
- 日付: 2026-11-18
- 関連: [#43](https://github.com/Ries630/StockCopilot/issues/43)

## 背景

`analyze.py` は日足・週足とも `fetch_ohlcv(..., limit=200)` で 200 本を取り、`lib/indicators.py` の
`compute()` に渡していた。`compute()` の EMA200 は `ta` の `EMAIndicator`（`ewm(span=200, adjust=False)`
相当）で、系列の最初の終値を初期値に置く再帰計算である。初期値の重みは 1 本ごとに
`1 - 2/201` 倍になり、200 本では `(1 - 2/201)^199 ≒ 13.7%` が残る。`compute()` の
`len(c) >= 200` の判定は NaN を出さないことを保証するだけで、値の収束は保証しない。

#43 の実測（日本株 1 銘柄の日足、2026-08-13 確定足）では、窓の本数ごとの収束値との差は
200 本で +3.9%、400 本で +0.2%、600 本で +0.02% だった。2026-08-19 の確定足では、
200 本の出力（4,197.4）が終値 4,097 の上、収束値（4,027.1）が終値の下になり、
「EMA200 割れ」と「EMA200 の上を維持」で判断の向きが逆になった。

## 決定

`analyze.py` が指標の計算に渡す確定足を 600 本（`HISTORY_BARS`）にする。全指標をこの系列で
計算し、`compute()` の入力の意味（渡された確定足の全体）は変えない。600 本では初期値の重みが
`(1 - 2/201)^599 ≒ 0.25%` まで下がり、#43 の実測でも収束値との差は 0.02% だった。

過去のジャーナルに残った EMA200 の数値は書き換えない。この ADR より前の EMA200 は
200 本の窓で計算した値で、収束値から数 % ずれうる。過去の記録と今回の値を比べるときは、
EMA200 の水準の差を価格の動きと読まない。

## 検討した代替

- **EMA200 だけ長い系列で計算する（#43 の案 A）。** 他の指標は末尾 200 本のまま保てるが、
  `compute()` の入力を「表示したい本数」と「EMA200 用の本数」に分けることになり、呼び出し側も
  2 つの本数を扱う。他の指標は長い系列で計算しても値が変わらない（下記）ので、分ける利点がない。
- **400 本にする（#43 の案 B の当初の値）。** 実測で +0.2% が残る。2026-08-19 の例では終値と
  収束値の差が約 1.7% だったので、400 本でも判断は変わらないが、600 本との取得コストの差は
  yfinance の 1 リクエストの期間が延びるだけで小さい。
- **EMA200 を SMA200 に置き換える（#43 の案 C）。** 初期値依存は消えるが、指標の意味が変わり、
  CryptoTradingCopilot から移植した指標セット（[ADR-0001](0001-separate-sibling-project.md)）から外れる。

## 受け入れた代償

- 取得する期間が日足で約 3 倍、週足で約 11.5 年分になる。
- OBV は窓の先頭からの累積なので、`obv` の絶対値が変わる。`obv_prev10` との差分は変わらない。
  RSI・MACD・ADX・ATR・StochRSI など他の再帰的な指標は、期間が短く 200 本の時点で収束しているので
  実質的に変わらない。
- `確定足 N本` の表示が 200 から 600 になる（履歴が短い銘柄はその本数）。
- 上場から 600 本に満たない銘柄の EMA200 は、上場時の終値の影響が残る。それより前のデータが
  存在しないため、窓を伸ばしても解消しない。200 本未満で出さない従来の判定は残す。

## 再評価の条件

- データ源を yfinance から差し替え、長期の履歴が取れなくなったとき（[ADR-0004](0004-yfinance-as-data-source.md)）。
- 指標に EMA200 より長い期間の再帰的な指標を足すとき。
