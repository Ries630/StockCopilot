# ADR-0015: ジャーナルの執行記録を決定的コードで読み、母集団の除外を実効保有で行う

- ステータス: 承認済み
- 日付: 2026-08-12
- 関連: [#31](https://github.com/Ries630/StockCopilot/issues/31)、[#26](https://github.com/Ries630/StockCopilot/issues/26)、[#23](https://github.com/Ries630/StockCopilot/issues/23)

## 背景

[#26](https://github.com/Ries630/StockCopilot/issues/26) で保有の定義を次のように変えた。

```
実効保有 = Investment の as_of 時点の保有 + ジャーナルに記録した以降の執行
```

`stock-check` (SKILL.md) はこの定義で動いている。一方 `screen.py` の母集団除外は
`lib/holdings.py` の `held_tickers()` を使っており、**Investment の `as_of` 時点の保有しか
見ていない**。ジャーナルの執行記録を参照していない。同じ「保有」の語が 2 つの意味で
使われている状態だった。

症状は 2 方向に出る。

- `as_of` 以降に買った銘柄が、スクリーニング候補として出うる（実害のある方向）
- `as_of` 以降に売った銘柄が、母集団から除外されたままになる（探索対象が 1 つ減るだけ）

前者が起きるには「`as_of` 以降に新規購入」「その銘柄が探索ユニバースに含まれる」
「機械条件を通過する」の 3 つが重なる必要があり、発生確率は低い。候補として出ても、
分析に回す前に保有銘柄だと気付ける。ただし**気付けるかどうかが人間の記憶に依存しており、
スクリーナーが「非保有銘柄の探索」であるという前提そのものが崩れている**。

判断の前提として分かっていたこと。

- `journal/journal.md` は人が書く Markdown で、追跡対象外（[ADR-0008](0008-no-holdings-in-repo.md)）。
  書式の正は `journal/README.md` にあり、ADR には書かない
- 執行記録の書式は「1 件につき残株数を必ず書く / その行だけで残高が確定する」と定めている
  （[#23](https://github.com/Ries630/StockCopilot/issues/23)）。書式の中で最も規律が効いている項目
- `held_tickers()` の呼び出し側は `screen.py` の 1 箇所だけ
- **実際に書かれている執行の節は、書式の正と揺れていた**（実装時に判明）。3 つの節のうち
  1 つが「約定日は `#### 執行 (2026-08-10)` の見出しにあり、残株数は字下げした子の行にある」
  という書き方で、テンプレートどおりの行は 1 件も無かった。ジャーナルは追記専用で
  **過去エントリは書き換えない**規約があるため、この揺れは消せない

## 決定

`lib/journal.py` に `### 執行` のパーサを置き、`lib/holdings.py` の `held_tickers()` が
実効保有を返すようにする。

- **機械が読むのは日付・ティッカー・残株数の 3 つだけ**。売買別・単価・約定代金は読まない
- 適用するのは、その銘柄の `as_of` 以降に記録された執行のみ。同日はジャーナルを優先する
- **既に書かれた揺れは読む側で吸収する。** 約定日は行頭に無ければ節の見出しから取り、
  残株数は字下げした続きの行まで探す。執行の行かどうかは `|` 区切りの有無で判定し、
  `|` を含まない箇条書き（節に書かれた補足の散文）は警告にもしない
- 解釈できない行は例外にせず、警告として呼び出し側に渡す
- `screen.py` は除外の内訳（`as_of` と適用した執行の件数、警告）を出力する。
  判定ロジックは足さない（[ADR-0006](0006-screener-does-not-decide-buys.md) の分離は維持）

## 検討した代替

- **執行記録を機械可読な別ファイルにも持つ** — 単一情報源の規約と正面から衝突する。
  採るなら「ジャーナルを生成物にする」という別の判断が先に要る。
  [ADR-0014](0014-defer-machine-readable-log.md) で機械可読ログを見送った判断とも整合しない
- **決定的コードでは対処せず、`stock-screen` スキル側で候補提示時に確認する** — 漏れる。
  スキルに判断を持ち込まない規範（[ADR-0006](0006-screener-does-not-decide-buys.md)）とも噛み合わない。
  このスキルはスケジュール実行される前提で、確認を求めて止まれない
- **対処しない（発生条件と影響を記録して閉じる）** — 影響は小さいが、保有の定義が
  `stock-check` と `stock-screen` で食い違ったままになる。`stock-screen` の SKILL.md には
  「`stock-check` と規範を揃えている。片方だけ変えないこと」と書いてあり、齟齬が残る
- **執行行の全項目（売買別・単価・約定代金）をパースする** — 除外判定には残株数だけで足りる。
  読む項目を増やすほど書式ゆれで壊れる箇所が増える
- **`held_tickers()` の戻り型を `set[str]` のままにし、黙って合成する** — 呼び出し側の変更は
  要らなくなるが、パースが壊れたことに誰も気付けない。A 案の弱点が検出不能になる

## 結果

- **`journal/journal.md` の `### 執行` が実装の入力になった。** 書式の正は `journal/README.md` の
  ままだが、書式を変えるときはコードの追随が要る。人が自由に書ける記録ではなくなった
- **記録の網羅性がスクリーナーの母集団に直結する。** 従来「保有銘柄が候補に出る」原因は
  `as_of` の古さだったが、これ以降は執行記録の漏れが原因になる。原因が人の運用側に移った
- **ティッカーを持たない執行は解釈できない行になる。** 投資信託などを書くと毎回警告が出る
- **実運用の書式ゆれはテストで守れない。** `journal.md` は追跡対象外で CI に存在しないため、
  テストが固定できるのは想定した書式だけになる
- **パーサが受理する形は `journal/README.md` の書式より広い。** 過去の揺れを吸収する分、
  「何が読めるか」は書式の正だけを読んでも分からず、`lib/journal.py` を見る必要がある
- **「予定」を執行の節に書くと毎回警告が出る。** 残株数の無い行は執行として読めないため。
  実際に 1 件そう書かれた行があり、警告として残る（黙って執行扱いにしないための挙動）
- `held_tickers()` の戻り型が変わり、呼び出し側は警告の扱いを書く必要がある
- 執行日と `as_of` が同日のとき、Investment 側が新しくてもジャーナルを優先する。
  誤る場合は「探索対象が 1 つ減る」低実害側に倒れるが、常に正しいわけではない

## 再評価のサイン

- 解釈できない行の警告が定常的に出るようになったら（実運用で書式ゆれが頻発するなら）、
  パース対象をさらに狭めるか、[ADR-0014](0014-defer-machine-readable-log.md) の機械可読ログ側に寄せる
- Investment の `as_of` が高頻度で更新される運用に変われば、この合成そのものが不要になる
