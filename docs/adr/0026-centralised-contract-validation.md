# ADR-0026: 中間表現の検証を集約し、severity を 2 段階にする

- ステータス: 廃止（ADR-0027 により置換）
- 日付: 2026-08-21
- 関連: [#60](https://github.com/Ries630/StockCopilot/issues/60) / [#64](https://github.com/Ries630/StockCopilot/pull/64) / [#71](https://github.com/Ries630/StockCopilot/issues/71) / [ADR-0020](0020-intermediate-report-json.md)

## 背景

[ADR-0020](0020-intermediate-report-json.md) で中間表現 JSON を挟み、
[`docs/report-contract.md`](../report-contract.md) をその仕様の正と定めた。当初、契約の
強制は `report.py` の中で、項目を使う場所ごとに行っていた。

この形では、条件分岐の中でしか使わない項目は検証が走らない。実例として `range` は
キーの存在しか見ておらず、`range_axis()` は `low` / `high` が無ければ空文字を返すため、
`range: {}` の候補をエラーも警告も出さずに描画できた。`notify.py` は別のコードパスなので、
同じ保証を共有する必要もあった。

一方、契約違反には性質の違いがある。`bars.us` の欠落はデータ鮮度を表示できない不備だが、
「買い」に `prose.weak` が無い場合は弱点を確認していない判断の質の問題になる。
このツールは個人用・単一利用者・発注機能なしであり、失敗の実害は不完全な HTML が出て
利用者が気づくことに留まる。

ただし、警告へ降格した欠落を黙って既定値に変えると、「問題が無い出力」と
「書き漏らした出力」を区別できない。[ADR-0016](0016-surface-unavailable-earnings-date.md) で
取得不能を「不明」と出すのと同じく、処理を続ける場合も欠落自体は利用者へ見せる必要がある。

## 決定

中間表現の検証を [`lib/contract.py`](../../lib/contract.py) の `validate()` に集約し、
`report.py` と `notify.py` は出力前に同じ検証を通す。

契約違反の severity を次の 2 段階にする。

| 段階 | 対象 | 挙動 |
|---|---|---|
| 例外 | 誤ると利用者の取る行動が変わる、または取るべき行動が見えなくなるもの | その場で停止する |
| 警告 | 表示の不備 | HTML と Slack の警告へ載せ、「不明」と表示して続行する |

具体的な割り当ては [`docs/report-contract.md`](../report-contract.md) を正とする。

## 検討した代替

### 契約違反をすべて例外にする

不採用。`bars.us` の欠落と「買い」に `prose.weak` が無い場合を同じ重さで停止させると、
表示だけの不備でも日次処理が止まる。判断に関わる違反は停止させたまま、表示の不備は
欠落を見せて続行する。

### JSON Schema を使う

（未検討）

### 生成側で不正な中間表現を作れないようにする

（未検討）

### 検証を持たず、何もしない

（未検討）

## 結果

表示の不備があっても、残っている情報から HTML を生成し Slack 通知を続けられる。
その代わり、警告を読み飛ばすと欠落した出力を使い続けられてしまう。呼び出し側は
`validate()` が返す警告を必ず利用者へ出し、欠落箇所は「不明」と表示しなければならない。

契約に項目を追加するときは、仕様の正である `docs/report-contract.md`、検証の実装である
`lib/contract.py`、検証項目の一覧を持つ `tests/test_contract.py` を揃えて変更する。

## 未検証の点

JSON Schema、生成側での予防、何もしない場合との比較は行っていない。このため、
ステータスは「提案」とする。

## 再評価のサイン

- 同じ警告が繰り返され、表示の不備が定常化したとき
- 警告の見落としによって利用者の判断へ影響が出たとき
- 契約項目が増え、JSON Schema と手書きの `validate()` を比較する必要が出たとき
- 同種の生成ミスが繰り返され、検出より生成側での予防を検討するとき

## 廃止の経緯

提案後、[ADR-0021](0021-json-schema-for-report-contract.md) により中間表現の構造検証へ
JSON Schema が採用された。手書き検証表へ置き換える前提では構造の正が二重化するため、
JSON Schemaを維持したseverity設計を [ADR-0027](0027-contract-validation-severity.md) で採用した。
