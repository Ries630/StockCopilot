# ADR-0020: 夕方ブリーフの出力に中間表現 JSON を挟む

- ステータス: 承認済み
- 日付: 2026-08-20
- 関連: [#60](https://github.com/Ries630/StockCopilot/issues/60) / [#61](https://github.com/Ries630/StockCopilot/issues/61)

## 背景

定期タスク `stock-copilot-evening-brief` は `stock-check` と `stock-screen` を順に実行し、
その分析全文をジャーナルと Slack に同じ形で流している。出力層が 1 つしかないため、
スマホで結果を確認する場面に合う粒度が存在しない。2026-08-20 のジャーナルエントリは
531 行あり、これがそのまま Slack に投稿される分量である。

兄弟プロジェクトの `trading-copilot-morning-brief` は
`機械判定 JSON → HTML ダッシュボード → チャット要約 → Slack push` の 4 層に分かれており、
読む場面ごとに粒度が違う。ただしあちらはシグナルが機械的に確定するため、
1 本のスクリプト (`morning_signal.py`) が判定から Slack 投稿まで完結できる。

株式側は事情が違う。`screen.py` は設計上ここで買い判断をしない
([ADR-0006](0006-screener-does-not-decide-buys.md))。判断ラベル
(ホールド / 積増し / 部分利確 / 売却 / 保留、買い / 見送り / 決算後に再判定 / 保留) は
`analyze.py` の指標を読んだ LLM の分析から出る。したがって morning brief と同じ
「全部スクリプト」の構成は取れない。

一方で、Slack のメンションを「資金が動く判断がある日だけ」に絞るには、
**判断ラベルを機械的に読める場所**が要る。LLM が書いた散文から抽出する形にすると、
発火条件が LLM の裁量に戻る。

## 決定

LLM の判断と機械データを合流させた中間表現 JSON
(`reports/YYYY-MM-DD_evening.json`) を挟む。HTML レポート (`report.py`) と
Slack 通知 (`notify.py`) は、どちらもこの JSON **だけ**を入力にする。

書式の正は [`docs/report-contract.md`](../report-contract.md) に置く。

## 検討した代替

**1. LLM が HTML を直接書く。** 却下。毎回レイアウトが揺れて日次の比較ができない。
スタイル規範を SKILL.md に写経することになり二重管理になる。さらに Slack の
メンション判定を HTML から取り出せず、発火条件が LLM の裁量に戻る。

**2. 全部スクリプト化する (morning brief と同形)。** 却下。買い判断を `screen.py` に
足すことになり [ADR-0006](0006-screener-does-not-decide-buys.md) に正面から反する。

**3. ジャーナルの Markdown を解析して HTML と通知を作る。** 却下。ジャーナルは人が読む
追記専用の文書で、書式の自由度が高い。`lib/journal.py` が機械可読に読んでいるのは
執行行の 3 項目だけで ([ADR-0015](0015-journal-executions-machine-read.md))、
判断や散文まで機械可読にすると、書式を少し変えるたびにパーサが壊れる。

## 結果

**LLM は分析結果を 2 か所に書くことになった** — ジャーナル (人間向けの正) と
中間表現 JSON (機械向けの正)。同じ内容が 2 か所に出るため食い違いが起こりうる。
片方から片方を生成する形にはしていない。

**契約の変更コストが上がった。** JSON の書式を変えると `report.py` と `notify.py` の
両方が追随する必要があり、加えてスキル側も書き方を知っている必要がある。
`docs/report-contract.md` を正に置いてリンクで参照させるが、参照点は 3 つに増えた。

**中間表現に入れなかった情報は、HTML にも Slack にも出ない。** ジャーナルにだけ書いた
観測はレポートから見えない。契約の項目を絞ったぶん、書ける内容の上限が決まった。

## 再評価のサイン

- JSON とジャーナルの食い違いが実運用で見つかったら、どちらかを生成物にする
  (ジャーナルを JSON から起こす等) を検討する
- `report.py` が契約違反で落ちる日が続くなら、スキーマ検証を足すか契約を緩める
- 判断ラベルの体系が変わったら ([ADR-0017](0017-screen-report-writes-verdict.md) の
  再評価)、契約とメンションのゲート条件を同時に見直す
