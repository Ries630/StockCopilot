# ADR-0009: 決算日はトリガーの有効性を判断するために取得する

- ステータス: 承認済み
- 日付: 2026-08-07
- 関連: `d555a36`、[#1](https://github.com/Ries630/StockCopilot/pull/1)

## 背景

保有分析は「日足終値で X を割ったら」という**確定足ベースのトリガー**を渡す
（[ADR-0005](0005-completed-bars-only.md)）。決算はギャップ要因であり、
このトリガーを**飛び越えて執行不能にする**。

`stock-check` の実運用テストで、トリガー水準まで 0.5% の銘柄が当日決算というケースが
実際に出た。決算日を取らないまま「X を割ったら」と書けば、執行できないトリガーを渡すことになる。

取得手段は yfinance の `yf.Ticker(symbol).calendar`
（データ源は [ADR-0004](0004-yfinance-as-data-source.md) で yfinance に閉じている）。
ETF は fundamentals を持たないため取得できない。個別株でも yfinance が小型株の
calendar を持たないことがある。

## 決定

`lib/datasource.py` に `fetch_next_earnings()` を置き、`analyze.py` の銘柄ヘッダに
次回決算日を併記する。前後 `EARNINGS_ALERT_DAYS = 7` 日以内は警告し、決算前は
「ギャップでトリガーが飛びうる」、決算後は「直近の値動きは決算反応の可能性」と
文言を出し分ける。

**日程を報告するために取るのではなく、そのトリガーが機能するかを判断するために取る。**

## 検討した代替

- **決算日を取らない** — 執行できないトリガーを渡すことになる。実運用テストで
  実際に起きたケースがあるため落とした
- （取得先の他案の記録は無い。データ源は [ADR-0004](0004-yfinance-as-data-source.md) に閉じている）

## 結果

- **取得できなかった銘柄では警告が出せない。** しかも個別株の `None` は
  「決算が無い」ではなく「**取得できなかった**」で、出力上この 2 つを区別できない
- **ETF では常に取得できない。** さらに 404 が yfinance 自前のロガーから毎回 stderr に出るため、
  正常な経路でエラー行が出る状態になった
  （[#15](https://github.com/Ries630/StockCopilot/issues/15) → `f471da7` で
  決算取得の呼び出し中だけロガーを抑制）
- **1 銘柄あたり 1 リクエスト増える。** `screen.py` では既定でオフにする必要が生じた
  → [ADR-0012](0012-shared-earnings-module.md)
- 決算前後の候補はエントリーの検討を決算後に回すことになり、決算期には分析に回せる
  候補が減る
