# ADR-0014: 機械可読ログは閾値と母集団が固まるまで作らない

- ステータス: 提案
- 日付: 2026-08-09
- 関連: [#9](https://github.com/Ries630/StockCopilot/issues/9)（OPEN）、[#14](https://github.com/Ries630/StockCopilot/pull/14)

## 背景

スクリーニング候補は `journal/journal.md` の `### スクリーニング` に人が読む 1 行として
残している。これは**継続の文脈**（前回何を候補に挙げたか、その後どうしたか）を追うための
記録で、散文なので集計には向かない。

「候補の精度を測る」= 「この条件で出した候補がその後どうなったか」の統計を取るには、
条件と結果が機械可読で揃っている必要がある。

ところが測定対象の条件にあたるものが両方これから動く。

- `MIN_BREAK_IN_ATR`（[ADR-0011](0011-event-based-screen-thresholds.md)、運用しながら調整する前提）
- 母集団（[ADR-0010](0010-three-layer-universe.md) のウォッチリスト、探索ユニバースの拡張）

## 決定

`screen.py --json` の出力を `journal/screen_log.jsonl` に 1 行 append する形を採る方針だけを
決め、**着手は閾値と母集団が固まってから**にする。`screen.py` 側は変更しない
（スクリーナーに書き込み責務を持たせない）。ログは追跡対象外にし、CI の追跡チェックに追加する
（[ADR-0008](0008-no-holdings-in-repo.md)）。

## 検討した代替

- **`journal/journal.md` に集計可能な形で書く** — 継続の文脈を追う散文の記録と用途が違う。
  媒体を分ける
- **今からログを貯め始める** — 条件が異なるログを混ぜて集計しても、閾値のせいなのか
  銘柄のせいなのか切り分けられず、測定として成立しない。集計する運用が立ち上がらないうちに
  ログだけ貯めても書き捨てになる

## 結果

- **着手までの期間の候補は、機械可読な形では残らない。** 後から遡って集計できない
- [ADR-0010](0010-three-layer-universe.md) によりウォッチリストの変更履歴が残らないため、
  ログを取り始めても「その時点の母集団」は完全には再現できない
- 候補の精度を測れるようになるまで、[ADR-0011](0011-event-based-screen-thresholds.md) の
  閾値と探索ユニバースの広さは実測ではなく運用感覚で調整することになる

## 未検証の点

- **何をもって「閾値と母集団が固まった」と判断するかは決めていない**（記録に無い）
- 未着手
