# ADR-0036: 保有中の長期保有枠は判断ラベルを 3 択に絞り、株数下限と権利落ちを注記する

- ステータス: 承認済み
- 日付: 2026-11-18
- 関連: [#59](https://github.com/Ries630/StockCopilot/issues/59)、[#56](https://github.com/Ries630/StockCopilot/issues/56)、[ADR-0007](0007-split-technical-and-fundamental-research.md)、[ADR-0035](0035-long-term-holding-slot.md)

## 背景

[ADR-0035](0035-long-term-holding-slot.md) で、優待や高配当を目的に長く持つ銘柄を長期保有枠として
`LONG_TERM_STOCKS` に置いた。買付予定の間は `screen.py` が期限までの残日数を出すが、
実効保有に入ったあとは他の保有と同じく `analyze.py` と `stock-check` が扱っていた。

保有中の長期保有枠に通常の保有と同じ読み方を当てると、次の 3 点がずれる。

1. テクニカル起点の部分利確は、優待の株数条件（`shares`）を割らせる。
2. 継続保有特典は、一度でも株数条件を割ると起算日がリセットされる。
3. 権利落ち日の下落は毎年起きる制度上の値動きだが、日足の変化率だけを見ると
   トリガー割れやシナリオ否定と区別がつかない。

1 と 2 のコストは価格に現れず、指標からは見えない。

## 決定

- `stock-check` は、長期保有枠として保有中の銘柄の判断ラベルを ホールド / 積増し / 保留 の 3 択に絞る。
  部分利確と売却はテクニカルからは提案しない。売却がありうるのは制度の廃止や業績の悪化など
  ファンダメンタルズの根拠がある場合だけで、その判断は dexter-jp が担う
  （[ADR-0007](0007-split-technical-and-fundamental-research.md)）。
- 中間表現の `holdings[].verdict` の語彙は変えない。長期保有枠かどうかは中間表現に載らず、
  3 択の制約は `stock-check` の規範として守る。
- `analyze.py` は、長期保有枠として保有中の銘柄に、目的 / 必要株数と現在株数 / 次の権利付き最終日
  までの残日数を注記する。現在株数が `shares` を割っていれば警告を付ける。
- 現在株数は、同じティッカーの実効保有の行（口座別）を合算した値とする。
- `analyze.py` は、日足の最新確定足が権利落ち日（`buy_by` のいずれかの翌営業日）なら、
  その下落が制度上の正常な値動きであることを注記する。権利落ち日は暦ではなく足の日付で判定する。
  直前の確定足の日付 ≤ `buy_by` < 最新確定足の日付 となる `buy_by` があれば、最新確定足を権利落ち日とみなす。
  指標値は変えない。
- 判定と文言は `lib/long_term.py` に置き、`analyze.py` は表示と JSON 出力だけを担う。

## 検討した代替

- **中間表現の語彙に長期保有枠用のラベル体系を足す** — 長期保有枠かどうかは追跡対象外の設定にしかなく、
  スキーマで検証するには中間表現に枠の所属を写す必要がある。所属を写すと購入意図の一覧が
  レポートに残る範囲が広がるので、まずはスキルの規範で守る。
- **権利落ちの下落ぶんを指標から差し引く** — 配当落ち・優待落ちの理論値を持たないので補正できない。
  補正した値は他の銘柄の指標と比べられなくなる。

## 受け入れた代償

- 3 択の制約はスキルの規範で、コードの検証では捕まえない。`stock-check` が規範を外れて
  部分利確を書いても、`lib/contract.py` は通す。
- 権利落ちの注記は日足の最新確定足だけに付く。翌日以降の分析や週足の変化率には権利落ちぶんが
  残るが、注記は付かない。
- 株数は口座をまたいで合算する。証券会社が違う口座は株主名簿で合算されないことがあり、
  合算値が `shares` 以上でも優待の条件を満たさない場合がある。
- 注記は保有モード（引数省略）でだけ出る。ティッカー指定では株数が分からないので出さない。
- `LONG_TERM_STOCKS` の書式の警告は `screen.py` だけが出す。`analyze.py` は読めた銘柄だけを扱う。

## 再評価の条件

- `stock-check` が長期保有枠に部分利確・売却を書いた例が出たとき（コードでの検証を検討する）。
- 権利付き最終日を決定的に取得できるデータ源が整ったとき（[ADR-0035](0035-long-term-holding-slot.md) と同じ条件）。
