# 分析ジャーナルの仕様

保有分析 (`stock-check`) の継続記録である `journal/journal.md` の書式と運用ルール。

## journal.md は git 追跡対象外

**`journal/journal.md` は `.gitignore` で除外している。** 中身が保有銘柄・株数・口座名・
売買判断の時系列＝個人の資産情報になるためで、このリポジトリが public であることが前提。
ジャーナル本体をコミットしてはならない。ここ (README.md) には書式だけを置く。

存在しない場合は `stock-check` が下記の書式で新規作成する。

## 書式

書式は TradingCopilot `swing/journal.md` に倣う。

- 1 回の分析 = 1 エントリ。見出しは `## YYYY-MM-DD`
- 銘柄ごとにシナリオ・主要水準・判断 (ホールド/積増し/利確) を残す
- 次回の分析は前回エントリとの突合から始める
- 過去エントリは書き換えない。訂正は新しいエントリに理由付きで書く
- 運用ルールとして固まった教訓は SKILL.md へ昇格させ、ここには経緯を残す

### エントリのテンプレート

```markdown
## YYYY-MM-DD (Investment as_of=YYYY-MM-DD)

- **9999** 銘柄名 | 現値 ¥X,XXX (前回比 +X.X%) | 判断: ホールド
  - キーレベル: 支持 ¥XXX / 抵抗 ¥XXX / 無効化 ¥XXX
  - シナリオ進捗: 前回シナリオが 前進 / 停滞 / 否定接近 のどれか (1 行)
  - トリガー: 日足終値で ¥XXX を割ったら◯◯
- **AAPL** 銘柄名 | 現値 $XXX (前回比 +X.X%) | 判断: 部分利確
  - (同上)
- 総括: 全体に共通するリスクと、優先アクション 1 つ (1〜2 行)
```

補足:

- **判断ラベルは ホールド / 積増し / 部分利確 / 売却 / 保留 の 5 種**に限る。信頼度の星は付けない
  (現物のホールド判断は perp より単純で、毎回付けると形骸化するため。swing-check とは異なる)。
  **「保留」はデータ不足で判定が成立しない場合のみ** — 上場後日が浅く週足や EMA200 が
  算出できない銘柄がこれにあたる。根拠なく「ホールド」と書くと継続保有の判断と区別できなくなる
- **決算が近い / 直近にあった銘柄はその旨を書く。** 決算はギャップ要因で、確定足ベースの
  トリガーを飛び越えて執行不能にする。日程の記録ではなくトリガーの有効性の問題として扱う
- 見出しに保有データの `as_of` を併記する。分析日と保有の基準日がずれるため、
  これが無いと後から「増減を見落としたのか、データが古かったのか」を切り分けられない
- 自動運用口座 (ロボアド等) の銘柄は判断対象外。書く場合は参考として明示する
- **トリガーは確定足ベースで書く** (「日足終値で」)。ザラ場の一時的な上下では判定しない
