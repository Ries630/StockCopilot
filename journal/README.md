# 分析ジャーナルの仕様

`journal/journal.md` の書式と運用ルール。

## 役割は 2 つだけ

**日々の分析はここに書かない。** 定型の分析（保有分析・スクリーニング・実効保有の提示・
前提・Slack 投稿結果）の正は `reports/YYYY-MM-DD_evening.json` で、人が読むのは
そこから生成される HTML レポート
（→ [`docs/report-contract.md`](../docs/report-contract.md) /
[ADR-0025](../docs/adr/0025-journal-as-ledger-and-memo.md)）。

このファイルが持つのは次の 2 つ。

| 役割 | 中身 | 誰が読むか |
|---|---|---|
| **① 執行の台帳** | 売買の記録（`### 執行`） | `lib/journal.py` が機械可読に読む |
| **② 運用メモ** | 定型に収まらないもの | 次回実行時にエージェントが読む |

**この 2 つは重複しない。** ①は分析の生成物ではなく、売買のたびに人が書く記録。
②は毎日は発生しない例外の記録。日々必ず出るものは JSON にあり、ここには無い。

### 過去エントリの扱い

**2026-08-20 までのエントリは定型の分析を含む。** 追記専用の規約により過去は
書き換えないため、書式は途中で変わる。読むときはこの切り替わりを前提にする。

## journal.md は git 追跡対象外

**`journal/journal.md` は `.gitignore` で除外している。** 中身が保有銘柄・株数・口座名・
売買判断の時系列＝個人の資産情報になるためで、このリポジトリが public であることが前提。
ジャーナル本体をコミットしてはならない。ここ（README.md）には書式だけを置く。

存在しない場合は執行 0 件として扱う（`lib/journal.py`）。

## lessons.md も追跡対象外

**`journal/lessons.md`** は、運用で判明した教訓のうち**再発防止のルールとして固まったもの**を
置く場所。スキルが実行の最初に読み、最後に書き足す。

②の運用メモとの違いは**確度**にある。1 回目の観測は運用メモ、繰り返して規則と言えるように
なったら lessons.md へ昇格させる。ジャーナルは追記専用で量が増え続け、書いたものが次回
読まれる保証がないため、必ず読まれる場所を 1 つ用意してある。

- 書き方は「ルール本体」+「経緯」の 2 部構成。経緯を落とすと、見直すときに前提が
  変わったかどうかを判断できない
- 汎用の規範（どのユーザーにも当てはまるもの）は SKILL.md 側に置く。ここに書くのは
  この運用に固有の事情から出た教訓だけ
  （→ [ADR-0018](../docs/adr/0018-bundle-skills-in-repo.md)）
- 無い場合は空として扱う（スキルは初回として続行する）

## ① 執行の記録

売買を `### 執行` に残す。**この節の書式がこのファイルの中心**で、変えるときはコードの
追随が要る。

これは記録のためだけの節ではなく、**保有の正しさを担保する台帳**である。保有データの出所
（Investment）の `as_of` はレポート生成では動かず、証券口座の残高を取り込んだときにだけ更新される。
その取り込みは高頻度では行わないため、`as_of` が古い状態が既定になる。そこで保有を次のように定める。

```
実効保有 = Investment の as_of 時点の保有 + ジャーナルに記録した以降の執行
```

`as_of` の鮮度に依存しなくなる代わりに、**この節の網羅性が保有の正しさそのもの**になる。

**`lib/journal.py` が機械可読に読む。** 読むのは各行の**約定日 / 銘柄 / 残株数の 3 つ**だけで、
`screen.py` の母集団除外がこれを Investment の保有と合成して実効保有を組む
（[ADR-0015](../docs/adr/0015-journal-executions-machine-read.md)）。解釈できなかった行は
`screen.py` の実行時に行番号付きの警告として出る（黙って無視はされない）。

### 書式

```markdown
## YYYY-MM-DD

### 執行

- YYYY-MM-DD | **9999** 銘柄名 | 売却 100株 @ ¥X,XXX | 約定代金 ¥XXX,XXX | **残 200株**
```

- **約定日は行頭に書く。** 過去エントリにある「見出しに日付を書き、残株数を子の行に置く」形も
  読めるようにしてあるが（追記専用で書き換えられないため）、新しい記録はこの書式に従う
- **「予定」をこの節に書かない。** 残株数が無い行は執行として読めず、毎回警告になる。
  予定は判断の側（中間表現の `prose.trigger`）に書き、約定したときにこの節へ記録する
- **売買した時点で記録する。** 分析を実行するときにまとめて思い出す形にしない。
  約定直後が単価・株数ともに最も正確で、後から思い出すと精度が落ちる
- **1 件につき書くもの**: 約定日 / 銘柄 / 売買別 / 株数 / 単価 / 約定代金 / **執行後の残株数**
- **残株数を必ず書く。** 差分（「-100株」）だけを積み上げる形にすると、1 件の記録漏れが
  以降すべての残高を狂わせ、しかも狂ったことに気づけない。残株数があれば、その行だけで
  残高が確定する
- **日本株は銘柄名を併記する。** 4 桁コードだけでは何の会社か分からない
  （→ [ADR-0023](../docs/adr/0023-japanese-stock-display-names.md)）
- 口座区分に触れるのは**税制上の差が判断に効く場合のみ**（NISA での売却など）
- **Investment の更新は「同期ポイント」として使う。** `as_of` が動いたときに、
  新しい保有と「古い `as_of` + 執行記録」を突合すれば、記録漏れをそこで検出できる。
  低頻度の更新が監査の役割を果たす

## ② 運用メモ

**定型に収まらないものだけ**を書く。毎日は発生しない。書くのは次の 4 種類。

### 訂正

過去エントリや過去の分析の誤りを、**原因つきで**記録する。原因を落とすと再発防止に使えない。

```markdown
### 訂正: YYYY-MM-DD の◯◯

何が誤りだったか。正しくは何か。
- 原因: なぜそう誤ったか（ここが本体）
```

**過去エントリは書き換えず、新しいエントリに訂正として書く。** 例外的に書き換えた場合は、
書き換えたこと自体を例外として残す（下記「規約の例外」）。

中間表現の JSON は 1 日 1 ファイルで、前日の判断が誤っていたと分かったときの置き場が
無い。訂正がここに来るのはそのため。

### 昇格候補の 1 回目の観測

「同種の事象がもう一度起きたら運用ルールへ昇格させる（今回は記録のみ）」という保留状態。

`lessons.md` は昇格**後**を置く場所なので、1 回目をここに残さないと、2 回目が来たときに
1 回目を思い出せず昇格を判断できない。**この節は lessons.md への待合室である。**

### 対話実行での追補と出典

定期実行では外部参照を行わないため「不明」としたものを、対話実行で確定させた記録。
実行モードによる外部参照の可否の正は
[`docs/output-contract.md`](../docs/output-contract.md)。

- **出典を必ず書く**（URL）。後から裏取りできないと、確定させた意味が無い
- **StockCopilot の決定的パイプライン外**の情報であることを明記する
  （→ [ADR-0004](../docs/adr/0004-yfinance-as-data-source.md) /
  [ADR-0007](../docs/adr/0007-split-technical-and-fundamental-research.md)）

### 規約の例外

規約に反する扱いをしたときの記録。「なぜ例外にしたか」と「何が食い違っているか」を書く。

例: 追記専用の規約に反して当日エントリを書き換えた／Slack の投稿と手元の記録が
食い違ったまま残っている（Webhook は投稿の `ts` を返さず、スレッド追補もできない
→ [ADR-0022](../docs/adr/0022-slack-webhook-notification.md)）。

### 書かないもの

- **銘柄ごとの継続メモ**（「この銘柄は決算日を手動で確認する」等）。
  [ADR-0016](../docs/adr/0016-surface-unavailable-earnings-date.md) が「手動確認リスト」として
  却下した案と実質同じで、恒常的な取得欠損の本筋は
  [#20](https://github.com/Ries630/StockCopilot/issues/20) にある
- **日々の分析・判断・キーレベル・シナリオ。** 中間表現 JSON が正
- **規範として固まった教訓。** `lessons.md` へ昇格させる
